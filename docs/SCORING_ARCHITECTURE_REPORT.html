1. Executive Summary

This report documents the full-universe Indian equity screener: classification, data fetching, multi-factor scoring, rule-based interpretation, and personalized recommendations matched to investor risk profiles.

Core principle: Sectors are curated in universe.yaml, not fetched from Yahoo Finance. yfinance supplies market data and fundamentals only.

Key capabilities

  • 181 NSE tickers across banking, IT, FMCG, pharma, auto, energy, metals, capital goods
  • Two-tier analysis: deep (Banking, IT — 7 risk questions) vs standard (5 questions)
  • Peer-relative scoring within sector cohorts (private vs PSU banks split)
  • Three-axis recommendations: Quality grade (A–F) · Peer band · Action label
  • Large-cap floor: Mega/large caps cannot fall below HOLD unless hard gates fail
  • Rule-based inference: YAML + Python; no LLM in the scoring path

Typical recommendation distribution

ActionApprox. share
STRONG BUY / BUY~30–35%
HOLD~40–45%
AVOID / SELL~20–25%

Design principles

  1. Sectors are curated in config, not from Yahoo.
  2. Two scoring engines: deep (Banking, IT) and standard (all others).
  3. Composite scores are peer-relative within cohorts.
  4. Recommendations use three axes before producing the action label.
  5. All inference is deterministic and rule-based.

Fetch flow (fetcher.py)

  1. Resolve ticker metadata from universe.yaml.
  2. Try yfinance via ticker_aliases.yaml (M&M.NS, CUB.NS).
  3. Pull get_info(), statements, 5y history.
  4. Compute returns, beta, volatility, drawdown vs ^NSEI.
  5. Banks: enrich_banking_metrics() merges curated ratios.
  6. sanitize_metrics() clamps outliers.
  7. Cache JSON 24h under .cache/screener/.

5. Pipeline & Quality Control

Orchestrator: screener/pipeline.py (ScreenState singleton for API)

fetch_all_metrics → QC filter → enrich_sector_relative_momentum → score_universe → interpret_universe

QC drop conditions

  • fetch_failed = true
  • sector_focus = unknown
  • price_history_rows < min_price_history_rows (default 20)
  • both PE and PB missing
  • data_completeness < min_completeness (default 0.35)

After QC: rs_vs_sector_pct = 6m return minus sector median 6m return.

8. Recommendation Engine (Three-Axis v3)

Axis 1 — Absolute quality (quality_grade.py)

quality_score = 0.45 × fundamental_strength
              + 0.40 × (composite_score / 100)
              + 0.15 × data_completeness
GradeCriteria
Aquality ≥ 0.75, no red flag
Bquality ≥ 0.55
Cquality ≥ 0.40
DBelow C or red flag with low quality
Fhard_gate_fail

Axis 2 — Peer band

BandPercentile
Top≥ 70
Upper-Mid50–70
Lower-Mid30–50
Bottom< 30

Axis 3 — Action label (action_matrix.py)

  1. Hard gate fail → SELL if Over, else AVOID
  2. Grade A/B + Top/Upper-Mid + not Over → STRONG BUY or BUY
  3. Grade A/B + Under → BUY (value opportunity)
  4. Grade A/B/C + not Bottom → HOLD
  5. Bottom + Over → AVOID
  6. Large-cap floor (≥ ₹500B): minimum HOLD unless hard_gate or red_flag
  7. Confidence < 0.35: downgrade one step on action ladder

9. Interpretation Engine

stock_analyst.py · signals.py · narrative.py

  1. Load 7 (deep) or 5 (standard) risk questions from YAML.
  2. Build context from metrics + score.
  3. Apply sector_risk_overrides.yaml band overrides.
  4. evaluate_signal() → good / warn / bad per question.
  5. stock_risk_score = weighted average (0–100).
  6. Re-run assign_action() after confidence update.
  7. Generate headline, bull/bear, key risk, verdict.
Analysis typeSectorsQuestions
DeepBanking, IT7 sector-specific

10. Profile Matching & Personalization

risk_matcher.py · risk_profile_matrix.yaml

Profile fit formula (0–100)

fit = 0.27 × risk_alignment
    + 0.25 × quality_norm
    + 0.18 × valuation_fit
    + 0.10 × profile_bonus
    + 0.20 × composite_score

Diversification rules

  • Top 20 picks total, max 3 per sector
  • Minimum 2 banking + 2 IT (deep_sector_min)
  • Conservative: excludes cyclical sectors, high beta, overvaluation

Output: FitResult with fit_score, quality_grade, peer_percentile, peer_band, action_label, reasons[].

13b. Scoring Engine Improvements (v2.1)

screener/scoring/adjustments.py · sector_bands.py · settings.yaml sector_calibration

P0 — Correctness

  • Quality grade decoupled from composite (85% fundamentals + 15% completeness only).
  • Banking peer cap: no Top band without GNPA or NIM; completeness penalty on composite.
  • Insurance: peer percentile disabled when cohort < 5 names.
  • Data QC: drop stocks with operating margin < −20% (bad feed), except large energy names.

P1 — Sector fidelity

  • Generic sectors read ROE, ROCE, margin, growth, D/E bands from sector_weights.yaml.
  • FMCG uses EBITDA margin when available.
  • Auto / Metals cyclical margin penalty applied inside composite.
  • Banking valuation label from P/B–ROE residual, absolute bands as fallback.
  • IT growth deduplicated to revenue CAGR + profit CAGR only.

P2 — Calibration & audit

  • Sector calibration: shift composites per cohort to target mean 57.5 before peer ranking.
  • Audit script: python scripts/sector_scoring_audit.py → docs/sector_scoring_audit.json
  • Golden-set backtest included in sector audit output.

14. Extending the System

Add a ticker

  1. Add to universe.yaml in the appropriate list.
  2. Verify yfinance symbol; add alias if needed.
  3. For banks: add banking_metrics.json entry.
  4. Run python cli.py screen --sector all --refresh.
  5. Check scripts/sector_audit.py.

Do not

  • Rely on yfinance sector for bucketing.
  • Compare composite scores across different peer cohorts.
